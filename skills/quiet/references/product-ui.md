# Product UI

Quiet is a **UI generalist**. Product surfaces are first-class. this is the gap versus marketing-only skills.

## Surfaces in scope

Chat / composers, sidebars and project trees, settings, dashboards, tables, diff/review, command palettes, dialogs, onboarding inside the app.

## Priorities

1. **Clarity and speed** over spectacle.
2. **Density with rhythm**. consistent rows, aligned columns, calm empty states.
3. **Shared primitives** in a `ui/` (or equivalent) layer.
4. **Motion discipline** from `motion.md` (almost always the product table, not the marketing table).
5. **State coverage**. empty, loading, error, overflow, long strings, reduced motion.

## Patterns

- Sidebars: readable hierarchy, restrained active states, no glass stack.
- Chat: message rhythm, composer clarity, no decorative gradients behind content.
- Settings: grouped forms, tabular numbers for usage, predictable control sizes.
- Dashboards: real data typography first; charts get contrast strokes / no dead legend hits. avoid fake dashboards.

## Cite restraint

When tempted to add a control or animation, ask Linear’s question: does this earn its place, or does it only survive because building is cheap?
